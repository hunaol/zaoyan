# V1.2 Windows 实机升级记录

日期：2026-10-16。此记录为更新包在目标 Windows / Docker 环境中的实际补验，区别于随包的开发环境报告。

## 应用与修复

- 校验更新包清单的全部 94 个条目与 SHA-256，当前源代码没有未知冲突；更新了 93 个文件，1 个文件已经一致。
- 保留已有 Dockerfile、Compose、Maven 配置、应用环境变量和 MySQL / 上传文件数据卷。
- 构建和隔离测试发现：已认证操作员访问其他人的实时会话时，拒绝访问异常经过错误分发被转为 401。已由 API 异常处理器直接返回 403；保留原有权限限制。
- Windows Docker Desktop 的旧通信套接字无法访问，普通及管理员权限下均无法重命名其父目录。经确认安装配置明确固定原 WSL 数据盘后，只对启动子进程使用新的本地运行缓存，避免访问故障套接字；没有重置 Docker 或删除业务数据。
- 冷启动复验还发现 Windows AF_UNIX 路径长度限制，已将运行缓存放在原 Docker 数据目录旁的短路径，并加入字节长度检查。该设置不写入系统环境变量，不迁移原数据盘。
- 外层和实际源码根目录均提供 start-docker.cmd。GitHub 使用说明已改为相对仓库路径，分别给出 Docker 和自行安装依赖的原生启动步骤。

## 验证边界

完整服务验收在 Docker 中执行；没有在 Windows 宿主机安装全部原生依赖并做完整原生启动验收。README 已分别列出原生启动所需软件和实际源码对应的命令。

浏览器摄像头硬件授权及真实食堂模型准确率未验收。内置测试素材是模拟素材，当前演示没有附带适配真实食堂的训练模型。

Docker 同类启动故障参考：[Docker 官方问题记录](https://github.com/docker/for-win/issues/15064)。本机父目录重命名仍失败，因此采用了经实机启动验证的独立运行缓存方式；该方式不是对 Docker 缺陷已经修复的声明。
